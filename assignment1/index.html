二、选题

标题：大观园——曹雪芹用一座园子写尽繁华与空虚 时长：约 90 秒（实际 83 秒） 画幅：竖屏 9:16 配音：情感男声（云希）

核心立意：不从单纯园林景观切入，采用反常识视角。大观园从建成那一刻就暗含虚空，它既是贾府繁华的顶点，也是衰败的开端。借元春省亲、众姐妹居住、园子荒芜，体现红楼繁华背后的悲剧感。

备选钩子（冲击感更强）：这座园子里住过最热闹的一群人，也埋着最盛大的一场葬礼。

为什么选这个题

拿名著练手，先跑通流水线：这一集不求单集多惊艳，而是验证"脚本→成片"能否一个人一天跑通。选题须满足三点：够国民、素材好找、没读过书也能懂——《红楼梦》天然契合。

单挑大观园，不碰宝黛爱情：宝黛之情已被讲透且缠绵太长，塞不进 90 秒；大观园是"盛衰的压缩包"——为元春省亲极盛而建，转身便是抄检、泪尽、出家，一个空间一条起落线刚好装下钩子。

只取一个反差：越繁华，越空虚：讲名著最忌复述全书。只要一个反常识切口——"最美的园子，像提前备好的盛大葬礼"，繁华与虚空一对冲，路人不必先读原著也能接住悲凉底色。

为真正的选题铺路：此集是模板验证，跑通后这套流水线可复用到后续数据新闻类作品。

三、策划

项目定位

AI 自动剪辑图文短视频，无需实景拍摄；采用标准化 90 秒内容模板：3 秒钩子→抛出核心观点→情节证据→反转深读→金句收尾→互动引导，模板可复用，批量制作《红楼梦》系列短视频。

90 秒节拍结构

配音实现说明（实际做法）

工具：edge-tts，音色 zh-CN-YunxiNeural（云希，情感男声）。
参数：--rate=-6% --pitch=-2Hz（整体比原文略慢、略低沉）。
字幕轴：edge-tts 自动生成 voice.vtt，按真实音轨切分 15 句，与画面逐句字幕对齐。
说明：口播稿中的逐句语速 / 重音标记为朗读意图与剪辑参考；本次 TTS 为整体统一降速，未逐句单独编码 SSML，金句处的情绪主要靠停顿与自然语调体现。

六、制作方法（实际流水线）

整套链路：脚本卡 → AI 生图 → TTS 配音 → HyperFrames 合成 HTML 视频源 → 无头浏览器逐帧渲染 + ffmpeg 编码 → 压缩优化 → 本地预览 → 发布。

步骤内容
1 脚本结构化确定钩子、观点、案例、反转、金句、引导语；写口播稿并标注语速/停顿/重音，输出 md
2 视觉素材生成用户按提示词用 AI 绘图工具生成 7 张 9:16 配图，按顺序命名放入 图片/
3 AI 语音合成edge-tts（云希）--rate=-6% --pitch=-2Hz 生成 voice.mp3，自动产出 voice.vtt 逐句字幕轴
4 HTML 视频源HyperFrames 把"图+配音+逐句字幕+转场（Ken Burns 缓推 / 省亲→抄检叠化）"合成 preview.html
5 逐帧渲染系统 Chrome 无头打开 preview.html 逐帧截图（2494 帧@30fps），ffmpeg 编码为 daguan.mp4（1080×1920，83s）
6 压缩优化ffmpeg 压出 daguan_web.mp4（720×1280，11MB），用于网页与上传
7 本地预览nginx 起服务，访问 http://localhost:8080 校对画面与字幕
8 发布推送 GitHub Pages（your-username.github.io）+ Cloudflare 加速；短视频平台另发

本流程为模板化流水线，更换选题文案与生图提示词，即可批量产出同系列视频。

八、项目总结

本项目是 90 秒人文向《红楼梦》短视频，主题为大观园解读。没有做平铺直叙的园林科普，使用「反常识钩子 + 情节证据 + 反转解读 + 金句」的短视频叙事模型。

采用 AI 图文成片的制作模式，不用实景拍摄，制作成本低，适配短视频平台完播逻辑。大观园不仅是书中的物理园林，更是一个文学符号，象征贾府虚幻的繁华，诠释《红楼梦》盛极而衰、万艳同悲的悲剧内核。

项目沉淀了一套完整可复用的生产模板：脚本结构化 → AI 生图 → edge-tts 配音 → HyperFrames 合成 → 无头渲染 + ffmpeg 编码 → 压缩发布。后续可快速切换人物、典故、伏笔类选题，批量产出整套红楼解读短视频；该流水线亦可搬用于数据新闻类作品。

归档材料：策划文档、口播脚本、AI 绘图提示词、字幕轴（voice.vtt）、成片（daguan.mp4 / daguan_web.mp4）、个人网站（index.html + nginx 配置）。
